# CLARIFY : 신규 법인 섭외 관련 ID/보안매체 이슈

> 대상: BBSB-231 (사용자권한관리) 관련  
> 작성 배경: 사용자 ID를 다수 사용하는 신규 법인 섭외 시 고객이 호소한 불편사항에 대한
> 현행 진단 / 타행 비교 / 최소 변동 개선안 정리  
> 참고자료: `corp_bank/` 하위 스토리보드 및 타행 이용가이드

---

## 1. 고객 Pain Point 정리 (원문 재구성)

| # | 이슈 | 세부 내용 |
|---|------|-----------|
| P1 | 신규 ID 채번이 어려움 | 신규 ID 채번 시 **영업점 방문 필수** → 관리자가 직접 사용자 정보를 셋팅할 수 없음 |
| P2 | 보안매체 강제 입력 | **최종 이체 실행자가 아닌 단순 이체 기안자**에게도 보안매체 입력을 강제하여 불편 |
| P3 | 로그인 자체가 불가 | 부산은행은 **보안매체가 없으면 인증서 발급 불가** → ID 로그인 자체가 불가 |
| R  | 제약조건 | 개발일정 매우 타이트 → **변동 최소화**한 해결방안이 필수 |

## 2. 현행 부산은행 설계 진단 (BBSB-231 스토리보드 기준)

### 2.1 사용자 생성/권한 설정 흐름
- `사용자관리 > 사용자정보` 화면에서 사용자 목록을 조회·관리 (slide 15~17)
- 사용자 정보 등록/수정 시 모든 저장 시점에 **보안매체 + 전자서명** 강제 (slide 10, 19, 22, 23, 27, 31, 33, 36, 39, 44)
- 상호점검 사용 기업은 저장 버튼 대신 **결재요청 버튼** 제공 (slide 11, 27, 36, 39)
- 보안매체 정책 (slide 4):
  - 관리자/서브관리자의 사용자정보·기업권한·업무권한·일반계좌권한·입금계좌권한·카드사업장권한 설정 → **보안매체 O, 전자서명 O**
  - 일반 사용자 → 본인 정보 확인만 가능 (변경 불가)

### 2.2 기안/결재제한 상태값
부산은행에도 이미 사용자별 **기안/결재제한** 필드가 존재함 (slide 15):
- `제한없음` : 결재선 지정 시 제약 없음
- `기안불가` : 기안자 지정 불가 → 결재자·승인자로만 등록 가능
- `단독결재불가` : 최종결재자·승인자로 등록 불가 (상위 결재자 필요)

→ 즉, **"기안 전용 ID" 개념의 반대(기안 불가)는 이미 있으나, "기안만 가능"한 경량 ID 개념은 정의/지원되지 않음**

### 2.3 보안매체 필수 지점 (slide 21, (공통)보안매체팝업)
사용자정보/권한 변경 전 지점마다 OTP 또는 보안카드 입력 팝업 호출 → 인증서 발급·로그인 자체가 보안매체에 종속.

## 3. 타행 비교

### 3.1 하나은행 — 웹ID (가장 유사한 솔루션)
`corp_bank/하나B_기업뱅킹가이드_사용자권한설정.pdf` Step 5~8

| 항목 | 내용 |
|------|------|
| 생성 주체 | **마스터 사용자가 기업뱅킹에서 직접 생성** (영업점 방문 불필요) |
| 권한 범위 | **조회 + 결재** 전용. 그 이외의 거래(=이체 실행 등)는 불가 |
| 보안매체 | **생성 시점에는 OTP/인증서 불필요** |
| 매체 필요 시점 | 조회·결재 이외의 거래가 필요해진 이후 → 영업점 방문해 OTP 부여, 기업뱅킹에서 인증서 발급 |
| 해지 | 마스터가 기업뱅킹에서 즉시 해지 |

→ **웹ID = 기안/결재 전용 경량 ID** 개념.  
→ 고객사 측이 "다수 사용자 ID 운영"을 가장 편하게 가져가는 전형적인 대응.

### 3.2 우리은행 — 결재자/조작자 분리 + 이체보안수단 추가 토글
`corp_bank/우리은행_..._직원이용자_권한설정.pdf` p.3

- 사용자 유형 : **결재자 / 조작자** 이분
- **이체보안수단 추가** 옵션: `없음` / `추가(결재 시 OTP + 우리인증서 입력 필요)`
  - 즉, 결재자라도 보안매체 입력을 **선택적으로** 적용 가능
- 조작자는 1일 이체실행한도 내에서 직접 출금, 결재자는 승인 가능한 한도만 보유 (p.6~7)

→ **보안매체 강제 여부를 "사용자/업무별로 설정" 가능**한 정책이 이미 설계에 반영됨.

### 3.3 요약 비교

| 항목 | 부산(현행) | 하나 | 우리 |
|------|-----------|------|------|
| 마스터가 ID 생성 | ❌ 영업점 방문 필수 (추정) | ✅ 웹ID | ✅ 직원이용자 신규등록 |
| 기안 전용 ID | ❌ (역방향 "기안불가"만 존재) | ✅ 웹ID (조회+결재) | 🟡 조작자/결재자 분리 + 보안매체 토글 |
| 보안매체 없이 로그인 | ❌ (인증서 발급 자체 불가) | ✅ (조회·결재에 한함) | 🟡 이체보안수단=없음 설정 시 완화 |
| 기안 시 보안매체 | 🟥 강제 | ✅ 최종 거래 시에만 | 🟡 토글 ("없음" 선택 시 생략) |

## 4. CLARIFY — 섹션별 확정 필요 질의

> 아래 항목은 개발 전에 **업무/보안/법무와 확정해야 하는 결정 포인트**입니다.

### Q1. 기안 전용(조회+결재) 경량 ID를 신규 도입할 것인가?
- 옵션 A: 하나은행 **웹ID** 방식 도입 → 사용자 유형 체계 추가 (기존 `관리자/서브관리자/사용자`에 `기안전용/웹ID` 추가)
- 옵션 B: 기존 `사용자` 타입에 **세부 플래그**만 추가 (아래 Q3 참조)
- 옵션 C: 우리은행 방식으로 사용자 타입을 `결재자/조작자`로 재설계 → **대규모 변경 필요**

→ **개발 최소화를 위해 옵션 B를 1차 후보로 제안** (현재 `기안/결재제한` 필드 확장만으로 커버 가능).

### Q2. 마스터의 ID 직접 생성(영업점 방문 배제)을 허용할 것인가?
- 허용한다면:
  - **어느 범위까지 허용?** (예: 이체 권한 없는 경량 ID만 비대면 생성 / 모든 ID 비대면)
  - **본인확인 수단?** (관리자의 보안매체+전자서명만으로 충분한지, 추가인증(휴대폰 본인인증 등) 필요 여부)
  - **한도·감사 통제** (일별 신규채번 한도, 내부통제 리포트 필수 여부)
- 규제/감사 관점에서 영업점 방문이 **제도상 필수**인지 확인 필요 (보안매체 자체 대면교부 요건과 분리될 수 있음).

### Q3. 기안자 단계에서 보안매체 입력을 면제할 수 있는가?
- 전자금융감독규정 상 **이체 실행 시** 추가인증(보안매체)이 요구되는 것으로 해석됨.
- 기안(=결재 요청 등록) 단계에서는 실제 자금이체가 발생하지 않으므로 **보안매체 면제 여지 존재**.
- 필요 결정:
  - (a) 기안 단계에서 보안매체 면제를 정책적으로 허용 가능한가? (보안·법무 컨펌 필요)
  - (b) 면제를 허용할 경우, **사용자 속성에 "기안시 보안매체 면제" 플래그**를 추가할 것인가, 아니면 **사용자 타입(경량ID)**에 귀속시킬 것인가?
  - (c) **최종 결재/이체 실행 시에는 기존대로 보안매체 필수** — 이는 변경하지 않음으로 설정 (규제 리스크 회피)

### Q4. 보안매체 없이도 로그인/인증서 발급이 가능해야 하는가?
- 현재는 "보안매체 미보유 → 인증서 발급 불가 → 로그인 불가"
- 하나은행 웹ID는 **보안매체/인증서 없이 로그인**이 가능 (조회·결재에만 접근)
- 결정 필요:
  - 경량 ID에 대해 **ID/PW + 추가인증(휴대폰, 간편인증)** 만으로 로그인 허용?
  - 또는 **공동인증서(개인)만 있으면** 로그인 허용? (인증서 발급에 보안매체가 엮이지 않도록 분리)
  - FDS·로그인 이상징후 모니터링 커버리지 확인

### Q5. 기존 "기안/결재제한" 필드와의 관계
- 현재 3개 상태(`제한없음` / `기안불가` / `단독결재불가`)를 그대로 두고,
  **사용자 속성에 "웹ID여부(=경량ID여부)"** 만 추가하면 최소 변경 가능
- 또는 "기안/결재제한"을 확장하여 `기안만가능` 상태를 새로 정의 — 어느 쪽을 취할지 결정 필요

## 5. 최소 변동 개선안 (권고 1안)

> 목표: 신규 법인 섭외를 위한 경량 ID 도입. 스키마/UI/업무 플로우 변화를 최소화.

### 5.1 개념
- 기존 사용자 테이블에 **`경량ID여부(light_id_yn)`** 속성 1개 추가 (또는 기존 사용자권한 구분값에 값 1개 추가)
- 경량ID의 특성:
  1. 권한 : **조회 + 기안**만 가능 (이체 실행/최종 결재 불가)
     - 업무권한설정에서 `이체-건별/다계좌이체` 등의 **실행 체크박스는 Disabled** + `기안/결재제한 = 기안불가`와 대칭적으로 **"기안전용"** 개념으로 해석
  2. 보안매체 : **보유 권장이나 필수 아님**
     - 기안 시 보안매체 팝업 **skip** (현재 slide 21 (공통)보안매체팝업 호출 부 조건 분기)
     - 최종 결재/이체 실행은 **기존 사용자(정상)** 가 수행 → 보안매체 필수 유지
  3. 생성 : 마스터가 기업뱅킹 화면에서 직접 채번 (하나은행 웹ID 방식)
  4. 해지 : 마스터가 즉시 해지 가능

### 5.2 변경 범위 (예상)
| 영역 | 변경 내용 | 규모 |
|------|-----------|------|
| DB | 사용자 테이블에 플래그 1개 추가 | 소 |
| 화면 - 사용자정보 | 등록 시 "경량ID 생성" 버튼/체크 추가 | 소 |
| 화면 - 업무권한설정 | 경량ID인 경우 실행 권한 자동 Disable | 소 |
| 공통 - 보안매체 팝업 | 호출부에 "경량ID + 기안 행위" 분기 | 중 |
| 로그인/인증서 | 보안매체 없는 경량ID 로그인 동선 정의 | 중~대 (별도 검증 필요) |
| 내부통제/감사 | 경량ID 채번·해지 로그 | 소 |

### 5.3 리스크
- **로그인·인증서 동선 변경**은 부산은행 공통 인프라(인증센터)와 엮여 있을 가능성이 큼 → **별도 영향도 분석 필수**
  - 만약 인증서 발급이 전행 공통 모듈에 종속되어 변경이 어렵다면, **1차 릴리즈는 "보안매체는 보유하되 기안 시 입력 면제"** 까지만 열고, "보안매체 없이 로그인"은 2차로 분리
- 규제 리스크 : 전자금융거래법상 접근매체 사용 기준 재검토 필요
