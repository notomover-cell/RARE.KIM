### 2.2 HIGH — 운영 이식 전 필수 수정

#### H1. innerHTML XSS sink in status renderer
- **위치**: `src/main.ts:223`
- **현상**: `helpTextEl.innerHTML = \`<b style="color:${color}">${msg}</b>\`` — `msg`에 `err.message`, `result.error` 등 네트워크/서버 발 문자열이 전달됨. MITM/프록시 변조 시 `<img src=x onerror=...>`가 live HTML로 실행 가능
- **영향**: 비대면실명확인 플로우 내 XSS → 은행 origin에서 세션 쿠키/후속 API 호출 탈취 가능
- **수정**:
  ```ts
  helpTextEl.textContent = msg;
  helpTextEl.style.color = color;
  helpTextEl.style.fontWeight = "bold";
  ```

#### H2. 카메라 LED가 페이지 unload/crash 후에도 유지될 수 있음
- **위치**: `src/main.ts`에 `pagehide`/`beforeunload` 핸들러 부재, `src/core/video-pipeline.ts:154-167`
- **현상**: `VideoPipeline`은 `visibilitychange`만 후킹. 사용자가 탭 종료·홈 버튼·충돌 시 `MediaStreamTrack.stop()`이 호출되지 않아 카메라 인디케이터/LED가 OS가 프로세스를 정리할 때까지 유지
- **영향**: PIPA §29 안전조치 위반 리스크, 고객 신뢰도 훼손, 언론 리스크
- **수정**:
  ```ts
  window.addEventListener("pagehide", () => { videoPipeline?.stop(); ringBuffer?.clear(); }, { capture: true });
  window.addEventListener("beforeunload", () => { videoPipeline?.stop(); ringBuffer?.clear(); });
  ```

#### H3. `multer@1.4.5-lts.1`는 EOL + 미수정 DoS CVE
- **위치**: `package.json`, `src/server/index.ts:14`
- **현상**: multer 1.x는 유지보수 종료. GHSA-g5hg-p3ph-g8qg (malformed multipart DoS), GHSA-rgv9-2q6p-j7j6 (메모리 고갈) 미수정
- **영향**: POC는 Mock 서버지만, 개발부가 이 패턴을 Java 백엔드로 복사할 위험
- **수정**: `multer@^2.0.0`으로 업그레이드 또는 `busboy`로 교체. POC에서 미리 안전한 버전으로 픽스

#### H4. Mock 서버 파일 사이즈·mimetype 제한 없음
- **위치**: `src/server/index.ts:14,38-76`
- **현상**: `multer({ storage: memoryStorage() })` with no `limits.fileSize`, no `fileFilter`. 단일 10GB POST가 RAM 전체를 소모. `cors()` 와일드카드까지 겹쳐 네트워크 내 누구든 DoS 가능
- **수정**:
  ```ts
  const upload = multer({
    storage: multer.memoryStorage(),
    limits: { fileSize: 2 * 1024 * 1024, files: 1, fields: 4 },
    fileFilter: (_req, file, cb) => cb(null, file.mimetype === "image/jpeg"),
  });
  ```

### 2.6 PIPA / 전자금융거래법 / 신용정보법 준수 진단

얼굴 이미지는 **개인정보보호법 §23 민감정보(바이오정보) + 신용정보법 §2**에 해당. POC는 **정신은 준수**하나 운영 전 2개 갭 close 필요:

**✅ 강점**
- 클라이언트 상 JPEG 미저장 (localStorage/IndexedDB/cookie/service-worker 전무 확인)
- Blob은 `Uploader.pending`에만 존재하고 `finally`에서 null 처리
- PIPA §29 수집 단계 최소 저장 원칙 충족

**⚠️ 갭 1 — 파기 증거 부재**
- PIPA §21은 파기 기록을 요구. 비정상 종료 시(탭 킬·강제 종료) 릴리즈 핸들러 없음
- **조치**: 위 H2의 `pagehide`/`beforeunload` 핸들러 + 파기 이벤트 로그(이미지 아님, 세션 ID + "cleared"만) — DPO 감사 대응

**⚠️ 갭 2 — 수집 고지 화면 부재**
- `main.ts:642`의 `startSession()`이 사용자 동의 없이 즉시 getUserMedia 발동
- 브라우저 권한 팝업은 PIPA 준수 동의가 아님
- **조치**: 운영 전 한국어 "개인정보 수집·이용 동의서" 화면 필수:
  - 수집항목: 얼굴 이미지 (JPEG)
  - 수집목적: 비대면실명확인
  - 보유기간: 수집 즉시 서버 전송 후 클라이언트 파기 / 서버는 ___년 보관 (백엔드팀 확정)
  - 거부권 및 불이익
  - 바이오정보 별도 동의 (§23-2)

**전자금융거래법 §21-2 인증수단**: 얼굴 인식은 보조 수단. 클라이언트는 촬영·업로드만, 서버 매칭은 인증된 eKYC 솔루션 담당 — 클라이언트 측 규제 이슈 없음

**신용정보법 §22-2 보호조치**: 서버 측 책임. 백엔드팀과 협의하여 업로드 JPEG이 저장 시 AES-256 암호화되고 보유 기간이 신용정보법 시행령 §17에 따라 ≤5년인지 확인 필요

#### C1. FSM 재시도 경로가 세션 시계를 초기화하지 않음 — 3회 재시도가 1프레임에 소진
- **위치**: `src/core/action-state-machine.ts:305-323` (`handleRetryOrFail`), `:137` (`beginPermission`이 `sessionStartedAt`을 설정하는 유일한 지점)
- **현상**: 타임아웃 시 `handleRetryOrFail`이 `aligning`으로 재진입하지만 `sessionStartedAt`을 갱신하지 않음. 다음 프레임에서 `feed()`가 `metrics.timestamp - sessionStartedAt > sessionTimeoutMs` 비교 → 즉시 재타임아웃. **스펙의 "15초 × 3회 재시도"가 실제로는 ~50ms 내 3회 모두 소진**
- **수정**: `handleRetryOrFail` 내에서 `this.sessionStartedAt = Date.now()` 초기화 + 타임아웃 유발 스트림 3회 연속 피드 → `retryCount === 3` + 총 ~45초 소요 검증 유닛 테스트 추가

#### C2. EAR gray zone 값에서 블링크 검출기 false positive
- **위치**: `src/core/metrics/ear.ts:58-80` (`isBlink`) + `action-state-machine.ts:250-266`
- **현상**: `closedMax=0.12`과 `openMin=0.18` 사이의 gray zone(0.12~0.18) EAR 샘플은 `closedRun`을 증가도 초기화도 하지 않음 → 느린 블링크가 gray zone을 스쳐 0.19로 튀면 spurious blink 발생. `sawClosedRun` 플래그가 윈도우 전체에 지속되어 과거 closed run 후 open 샘플이 나타나면 late `true` 반환
- **수정**:
  1. tri-state 명시적 전이 (`CLOSED → OPEN`은 직전 non-gray 샘플이 CLOSED였을 때만)
  2. gray zone 샘플은 `closedRun` 유지 (초기화/증가 없이 hold)
  3. 경계 테스트 추가: `closedMax` 정확히, `openMin` 정확히, gray 3연속

#### C3. `main.ts` SRP 위반 + EAR 임계값 3중 정의
