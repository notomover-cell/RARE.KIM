## 1. 개요

### 1.1 배경
- 현행 비대면실명확인(`MWPTBMAN0000020`) 중 신분증 촬영(`MWPTBIM50000000`)은 수동 셔터 촬영만 지원
- 얼굴 촬영 단계는 현재 안면인식 솔루션이 단일 정적 사진 1장만 받는 구조 → 위·변조 공격에 취약, 사진 품질 편차 큼
- 개선: 클라이언트에서 **액티브 라이브니스(행동 유도) + 자동 베스트컷** 방식으로 서버에 전달되는 이미지 품질을 높임

### 1.2 목적
- 부산은행 모바일웹(m.busanbank.co.kr) 상에서 동작하는 **얼굴 촬영 전용 라우트 페이지** 신규 구축
- 사용자가 정면을 보고 눈을 깜빡이면 클라이언트가 자동으로 최적 프레임을 선정하여 서버에 업로드
- 업로드된 이미지는 기존 안면인식 솔루션이 받아 얼굴 검증 + 신분증 대조를 수행 (**서버단 검증 로직은 본 범위 밖**)

### 1.3 범위
- **포함**: 모바일웹 프론트엔드 얼굴 촬영 페이지, 클라이언트 액션 검증, 베스트컷 스코어링, JPEG 업로드
- **제외**: 서버단 라이브니스 판정, 얼굴 매칭, 신분증 OCR/대조 (기존 솔루션 활용)
- **제외**: 네이티브 앱(굿뱅크) 카메라 API (단, 동일 JSP가 WebView로 렌더링되는 점은 고려)

### 2.1 기능 요구사항
| ID | 요구사항 |
|----|---------|
| FR-01 | 페이지 진입 시 `navigator.mediaDevices.getUserMedia()`로 전면 카메라 스트림 획득 |
| FR-02 | 풀스크린 비디오 프리뷰 + 중앙 타원형 가이드 오버레이 표시 (내부 밝게, 외부 rgba 0.55 dim 처리) |

| FR-05 | EAR(Eye Aspect Ratio) 기반 블링크 감지 — 4프레임 이상(~67ms) 눈 감은 상태 후 뜨는 전이만 유효 |

| FR-07 | 선정된 프레임을 **단일 JPEG(Quality 0.92)** 으로 인코딩하여 `POST /api/face-capture`에 멀티파트 업로드 |
| FR-08 | 업로드 성공 시 결과 콜백/세션 파라미터로 부모 플로우에 결과 전달 |
| FR-09 | 타임아웃(15초) 또는 연속 블링크 실패(2회) 시 재시도 UI 또는 수동 모드 fallback |
| FR-10 | 카메라 권한 거부 시 안내 메시지 + 이전 화면 복귀 |
| FR-11 | 페이지 이탈 시 `MediaStreamTrack.stop()` 전체 호출로 카메라 LED/권한 해제 |

## 4. 아키텍처

### 4.1 모듈 구성
```
CameraModule (public entry)
├── VideoPipeline            - getUserMedia 생명주기, playsinline, visibilitychange
├── WebViewHost              - UA 파싱, WKWebView/Android WebView/Chrome 분기
├── FaceLandmarkerRunner     - MediaPipe FaceLandmarker 래핑 (EAR + headPose 추출)
├── ActionStateMachine       - 10-state FSM (idle → permission → preview → aligning
│                              → align_hold → blink_prompt → blink_detecting
│                              → blink_confirmed → captured → uploading → done)
├── RingBuffer               - 직전 N프레임(full-resolution ImageBitmap) 보관
├── BestCutScorer            - 3축 가중합 스코어링(선명도/빛반사/정렬도)
├── JpegEncoder              - OffscreenCanvas.convertToBlob (Path A) /
│                              HTMLCanvasElement.toBlob (Path B, iOS Safari 15~16.3)
├── Uploader                 - multipart/form-data POST, 5xx 재시도
└── UIController             - 오버레이 가이드/안내문구/접근성 DOM 조작
```

### 4.2 런타임 데이터 플로우
```
사용자 진입
    │
    ├─ VideoPipeline.start()   ─┐
    │                           ├─ Promise.all (병렬 초기화)
    ├─ FaceLandmarkerRunner    ─┘
    │      .create()
    ▼
getUserMedia 권한 팝업 → 스트림 획득
    │
    ▼
[RAF 프레임 루프 시작]
    │
    ├─ FaceLandmarker.detect(videoEl, ts)
    │        → { landmarks, headPose, ear, faceBox }
    │
    ├─ createImageBitmap(videoEl) → RingFrame(fullBitmap + metrics)
    │        → ringBuffer.push(frame)
    │
    └─ fsm.feed(metrics)
             │
             ├─ aligning → align_hold (1000ms 유지)
             │      → blink_prompt → blink_detecting
             │      → onBlinkConfirmed 이벤트 발생
             │
             ▼
    [캡처 & 업로드]
    ringBuffer.snapshot() → ear ≥ 0.18 필터 (눈 뜬 프레임만)
        → scorer.pickBest() → RingFrame (full bitmap 소유권 이전)
        → encodeJpeg(bestFrame) → Blob
        → uploader.upload(jpeg, meta) → POST /api/face-capture
        → 응답 { ok, id, uploaded_at } → onComplete 콜백
```

### 5.2 FSM 상태 전이
| 상태 | 진입 조건 | 종료 조건 | 안내 문구 |
|------|----------|----------|----------|
| `idle` | 초기 | 페이지 진입 | (splash: "카메라 로딩 중...") |
| `permission` | splash 이후 | getUserMedia 성공 | 스플래시 유지 |
| `preview` | 권한 획득 | 첫 프레임 수신 | 스플래시 페이드아웃 |
| `aligning` | 비디오 첫 프레임 | yaw/pitch/roll ±30° 이내 | "얼굴을 화면 안에 맞춰주세요" |
| `align_hold` | 정렬 진입 | 1000ms 연속 유지 | "그대로 유지해주세요..." |
| `blink_prompt` | 정렬 완료 | (즉시) | "눈을 감았다 떠주세요" |
| `blink_detecting` | prompt 이후 | EAR 4프레임 closed → open 전이 | "눈을 감았다 떠주세요" |
| `blink_confirmed` | 블링크 감지 | 베스트컷 선정 | "촬영 중..." |
| `captured` | 프레임 선정 | 인코딩 완료 | "촬영 중..." |
| `uploading` | 업로드 시작 | 서버 응답 | "업로드 중..." |
| `done` | 업로드 성공 | - | "완료" + 썸네일 |

### 5.3 상태 전이 중 실패 경로
- **정렬 중 얼굴 이탈** (pitch/yaw/roll 임계 초과 또는 `landmarks=null` 2프레임 연속) → `aligning`으로 되돌아가고 `align_hold` 타이머 리셋
- **블링크 중 정렬 이탈** → `aligning`으로 되돌아가고 EAR 버퍼 초기화 (헤드틸트로 인한 눈꺼풀 가림 오인식 방지)
- **타임아웃(15초)** 또는 **블링크 재시도 초과(2회)** → 수동 촬영 fallback 또는 에러 화면 리다이렉트

## 6. 핵심 알고리즘

### 6.1 얼굴 정렬 판정 (`AlignmentGate`)
```
aligned = abs(yaw) ≤ YAW_MAX
        && abs(pitch) ≤ PITCH_MAX
        && abs(roll) ≤ ROLL_MAX
```
- yaw/pitch/roll은 MediaPipe `facialTransformationMatrixes`의 4×4 회전 행렬에서 PnP 역산 (OpenGL 컨벤션)
- 임계값 기본: **각 축 ±30°** (POC 튜닝 결과, 손에 들고 화면 내려보는 자세 허용)

### 6.2 EAR(Eye Aspect Ratio) 블링크 감지
- 공식 (Soukupová & Čech 6-point):
  ```
  EAR = (‖p2 - p6‖ + ‖p3 - p5‖) / (2 × ‖p1 - p4‖)
  ```
- 좌/우 눈 EAR 평균을 사용
- 랜드마크 인덱스 (MediaPipe 478-point):
  - 좌안: `[33, 160, 158, 133, 153, 144]`
  - 우안: `[362, 385, 387, 263, 373, 380]`
- **슬라이딩 윈도우 방식 블링크 판정**:
  - closed: `EAR ≤ 0.12`
  - open: `EAR ≥ 0.18`
  - 최소 연속 closed 프레임: 4 (≈67ms @ 60fps)
  - 롤링 윈도우: 25프레임 (≈417ms)
  - closed run이 4프레임 이상 발생한 뒤 open 프레임이 나타나면 **블링크 확정**

### 6.3 베스트컷 스코어링 (3축 가중합)
```
score(frame) = w1 × sharpness(frame)
             + w2 × reflectionFree(frame)
             + w3 × alignment(frame)
```
- **sharpness**: Laplacian 분산 (Y 채널 기준), 값이 클수록 선명
- **reflectionFree**: 얼굴 bbox ROI의 휘도 히스토그램에서 극고휘도(V≥250) 픽셀 비율, 비율이 낮을수록 안경/조명 반사 없음
- **alignment**: `1 - (|yaw|+|pitch|+|roll|) / 90` (정면에 가까울수록 높음)
- **기본 가중치**: `w1:w2:w3 = 0.4 : 0.3 : 0.3`
- **안전 경계**: `w2 ≥ 0.2` (빛반사 축 최소 기여도 보장)
- **튜닝 트리거**: POC 세션 중 유효 프레임의 5% 이상이 빛반사 오탐으로 배제되면 w2를 0.05씩 감소
- **Top-1 선택**: 스냅샷 내 **눈 뜬 프레임만** (`ear ≥ 0.18`) 후보로 삼고 가중합 최고점 선정

### 6.4 링버퍼 (`RingBuffer`)
- 용량 기본 **20프레임** (~333ms @ 60fps)
- 각 `RingFrame`은 **full-resolution `ImageBitmap`을 단일 소유**
- FIFO 축출 시 `ImageBitmap.close()` 즉시 호출 (GPU 텍스처 해제)
- 베스트컷 선정 후 `detach(winner)` 로 소유권 인코더에 이관 → 나머지는 `clear()` 로 일괄 해제
- **핵심 불변식**: 스코어러가 평가한 프레임과 JPEG 인코더가 실제로 받은 프레임은 **반드시 동일** — 썸네일 기반 스코어링 + 원본 재샘플링은 금지 (live MediaStream은 과거 프레임 seek 불가)

## 7. 서버 인터페이스 계약

### 7.1 업로드 요청
```
POST /api/face-capture
Content-Type: multipart/form-data; boundary=...

--boundary
Content-Disposition: form-data; name="image"; filename="face.jpg"
Content-Type: image/jpeg

<JPEG binary, quality=0.92, 원본 해상도>
--boundary
Content-Disposition: form-data; name="meta"
Content-Type: application/json

{
  "capturedAt": 1712817234567,    // performance.now() 기준 밀리초
  "sessionMs": 3281,               // 세션 총 소요 시간
  "score": {
    "sharpness": 0.82,
    "reflectionFree": 0.96,
    "alignment": 0.91,
    "total": 0.888
  }
}
--boundary--
```

### 7.2 업로드 응답 (정상)
```json
{
  "ok": true,
  "id": "9cd9c9e8-2254-4585-8c47-4c1e96ad63b2",
  "uploaded_at": "2026-04-11T07:25:42.123Z",
  "size": 143280
}
```

### 7.3 업로드 응답 (오류)
| Status | 응답 body | 클라이언트 처리 |
|--------|-----------|----------------|
| 400 | `{ "ok": false, "error": "missing image field" }` | `onError({ code: "internal", ... })` |
| 413 | `{ "ok": false, "error": "payload too large" }` | 재시도 금지, 에러 화면 |
| 5xx | (임의) | 5xx는 최대 2회 자동 재시도 후 실패 |

### 7.4 클라이언트 에러 코드 (`SessionError`)
```ts
type SessionErrorCode =
  | "permission_denied"      // getUserMedia NotAllowedError
  | "timeout"                // 15초 타임아웃 또는 재시도 초과
  | "upload_failed"          // 서버 응답 오류
  | "webview_unsupported"    // getUserMedia 미지원 환경
  | "internal"               // 예상치 못한 예외
  | "cancelled";             // 사용자 취소
```

## 8. 기존 시스템 통합

### 8.1 ib20 채널 등록
- **신규 메뉴 ID**: `MWPTBIM6xxxxxxx` (실제 코드는 채널개발팀 협의 후 확정)
- **진입 경로**: `MWPTBMAN0000020` (비대면업무 메인) → `MWPTBIM5xxx` (신분증 촬영) → `MWPTBIM6xxx` (얼굴 촬영, 신규)

### 8.3 주의사항 (POC 구현 중 발견된 이슈)
- `#unsupported_container` 스타일 룰에 `display: flex`가 있을 경우 `hidden` 속성이 무시되어 전체 화면을 가릴 수 있음 → **반드시 `#unsupported_container[hidden] { display: none !important; }` 룰 추가**
- 모바일 브라우저에서 `.pic_face > .scrollBox > .video_wrapper` 체인이 0px로 접히는 현상 발견 → `.pic_face`에 `position: fixed; top: 56px; bottom: 0; width: 100vw; height: calc(100dvh - 56px)` 명시 필요
- `<video>` 엘리먼트는 HTML 파서가 생성한 것을 재사용 (iOS Safari는 `document.createElement("video")` + `srcObject` 조합에서 렌더링 버그 발생)
- getUserMedia는 **HTTPS 필수** (localhost 제외). 운영 이관 시 동일 도메인 동일 origin 서빙 확인 필요

## 9. 구성 파라미터 (운영 이식 시 튜닝)

### 9.1 액션 검증
| 파라미터 | 기본값 | 설명 |
|---------|-------|------|
| `alignment.yawMaxDeg` | 30 | 좌우 회전 허용 범위 (손에 들고 사용 고려) |
| `alignment.pitchMaxDeg` | 30 | 상하 회전 허용 범위 |
| `alignment.rollMaxDeg` | 30 | 기울어짐 허용 범위 |
| `alignHoldMs` | 1000 | 정렬 유지 필수 시간 (ms) |
| `faceLostFrameThreshold` | 2 | 얼굴 소실로 판정할 연속 null 프레임 수 |

### 9.2 블링크 감지
| 파라미터 | 기본값 | 설명 |
|---------|-------|------|
| `earBlinkClosedMax` | 0.12 | 이 값 이하면 "감음" 판정 |
| `earBlinkOpenMin` | 0.18 | 이 값 이상이면 "뜸" 판정 |
| `earMinClosedFrames` | 4 | 의식적 블링크로 인정할 최소 연속 감은 프레임 수 (~67ms) |
| `earRollingWindow` | 25 | 블링크 감지 슬라이딩 윈도우 크기 |

### 9.3 세션·업로드
| 파라미터 | 기본값 | 설명 |
|---------|-------|------|
| `sessionTimeoutMs` | 15000 | 세션 전체 타임아웃 |
| `maxRetries` | 3 | 정렬/블링크 재시도 총 횟수 |
| `maxBlinkRetriesBeforeFallback` | 2 | 이 횟수 이후 수동 촬영 모드 진입 |
| `ringBuffer.capacity` | 20 | 링버퍼 최대 프레임 수 (iPhone SE 등 저사양 기기는 12로 다운그레이드) |
| `jpegQuality` | 0.92 | JPEG 인코딩 품질 (0.0~1.0) |
| `scoreWeights` | `0.4:0.3:0.3` | 선명도 : 빛반사 : 정렬도 |
| `uploadRetryCount` | 2 | 5xx 응답 시 재시도 횟수 |

### 9.4 MediaPipe 에셋
- WASM 바이너리 + 모델 파일은 **반드시 same-origin 서빙** (CDN 금지, 무결성·속도·개인정보 사유)
- 배포 경로: `/resource/js/mwp/vendor/mediapipe/vision_wasm_internal.js`, `/resource/js/mwp/vendor/mediapipe/vision_wasm_internal.wasm`, `/resource/js/mwp/vendor/mediapipe/face_landmarker.task`
- 파일 해시 버전 관리(`?v=V20260411000001` 패턴) + `Cache-Control: public, max-age=31536000, immutable` 헤더 적용
- 총 용량 약 15MB — 최초 진입 시 네트워크 품질에 따라 1.5~3초 소요. `<link rel="preload">` 힌트 적용 권장
- **라이트 모델 폴백**: 첫 사용자 기준 `FaceLandmarker.createFromOptions`가 800ms 이상 소요되면 `face_landmarker_lite.task`(약 1.5MB)로 자동 전환하는 로직 배포 직전 확정 필요
